# Contextual Retrieval（情境化檢索）

- C50：傳統 RAG 切塊後會丟失上下文。例子：某一塊只寫「公司營收比上一季成長 3%」，卻沒說是哪家公司、哪一季，檢索時就很難被對的問題找到。 [S3]
- C51：Contextual Retrieval 的做法：用 LLM 替每一塊產生一小段（通常 50–100 token）說明它在整份文件中的位置與背景，附在該塊前面，再做嵌入並建立 BM25 索引。 [S3]
- C52：Contextual Embeddings 讓「前 20 塊沒撈到相關內容」的比例降低 35%（5.7% → 3.7%）。 [S3]
- C53：再加上 Contextual BM25，失敗率降低 49%（5.7% → 2.9%）。 [S3]
- C54：再加上重排序，失敗率降低 67%（5.7% → 1.9%）。 [S3]
- C55：搭配 prompt caching，替每塊產生情境說明的一次性成本，Anthropic 估計約為每百萬個文件 token 1.02 美元。 [S3]
- C56：如果知識庫小於 200,000 token（約 500 頁），可以直接把全部內容放進提示詞，不需要 RAG。 [S3]
- C57：上述實驗的衡量指標是 1 − recall@20，也就是「前 20 塊裡沒有撈到相關內容」的比例，數字越低越好。 [S3]

⚠ 注意（見 log L-04）：搜尋結果中有第三方頁面引用 3.5%、1.9%、1.3% 這組數字，與 Anthropic 原文不符。本 wiki 一律採用原文（S3）的 5.7% → 3.7% → 2.9% → 1.9%。
⚠ 注意：35% / 49% / 67% 是「失敗率的相對降低幅度」，不是「準確率提升幅度」。
