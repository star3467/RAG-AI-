# RAG 的風險與維運

- C90：資料投毒：攻擊者把惡意或誤導的內容放進知識庫，一旦被檢索到，模型就可能產生看似可信卻錯誤的答案。 [S4]
- C91：提示注入：惡意指令藏在被檢索回來的文字裡，可能蓋過原本的指令，讓模型洩漏資料或略過防護。 [S4]
- C92：敏感資料外洩：私人或受管制的資料可能透過檢索或生成被暴露，需要存取控制（RBAC／ABAC）與敏感內容過濾。 [S4]
- C93：外部 API 依賴：嵌入、檢索或生成若依賴第三方服務，服務被入侵或中斷時，系統也會跟著受影響。 [S4]
- C94：防護原則：把每一筆輸入與檢索結果在證明安全之前都視為不可信。 [S4]
- C95：維運面：知識庫要定期更新才不會回答過時內容，向量資料庫也要針對速度與規模調整。 [S4][S6]

> 與作業的連結：C94 的「檢索內容不可信」原則，也適用於本次 workflow——從網路取回的內容，在寫進 wiki 之前要先檢查（見 log.md）。
