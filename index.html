RAG 是什麼？
讓 AI「先查資料，再回答」

從「AI 為什麼會亂答」出發，一步一步看懂檢索增強生成（Retrieval-Augmented Generation）。

知識來源：自建的 RAG LLM Wiki（6 篇來源）　·　2026-11-23　·　按 → 或空白鍵翻頁

ROADMAP今天要回答五個問題

① 為什麼需要？

AI 為什麼會答錯，RAG 想解決什麼。

② 怎麼運作？

從文件到答案的兩個階段。

③ 怎麼找得準？

切塊、向量、關鍵字、重排序。

④ 怎麼更進階？

Contextual Retrieval 與 Agentic RAG。

⑤ 要注意什麼？

成本、時機與資安風險。

學完之後，你可以用自己的話向朋友解釋 RAG，並判斷什麼情況該用它。

WHYAI 為什麼會「很有自信地答錯」？

① 知識停在訓練那一天

模型只靠訓練資料回答。遇到新資訊或冷門領域，內容可能已經過時。

② 不知道時會「編」

語言模型能寫出很流暢的句子，但流暢不代表正確，這種現象叫幻覺。

三個實務痛點：會產生幻覺　·　知識更新慢　·　答案不透明（看不出依據是什麼）。RAG 就是針對這些痛點而生。

RAG 的三項好處：有依據（答案連到可查證的資料，降低幻覺）　·　可擴展（換知識庫就能換領域）　·　成本較低（不必為每次知識變動重新微調）。

WHATRAG：先查資料，再回答

回答之前，先從外部知識庫找出相關資料，附進提示詞，再讓語言模型根據它們生成答案。

比喻

就像把「閉書考試」改成「開書考試」：考生（LLM）遇到題目，先翻參考書（知識庫），再寫答案。
（比喻，非來源）

兩種記憶

參數記憶：存在模型權重裡的知識。
非參數記憶：放在外部、可直接修改的索引。
換掉外部索引就能更新知識，不用重新訓練。

「RAG」這個名稱來自 2020 年 Lewis 等人的論文。

HOWRAG 的兩個階段

階段一：離線建立索引（事先做好）
文件→ 切塊→ 轉成嵌入向量→ 存進向量資料庫
階段二：線上回答（每次提問都會跑）
問題→ 轉成向量→ 相似度搜尋→ 取前 k 筆→ 附進提示詞→ LLM 生成答案
關鍵規則：問題和文件要用同一個嵌入模型轉成向量，兩邊才能互相比較。

還有兩點：錯誤會一路往下傳（嵌入差 → 檢索差 → 答案差）；附進提示詞的內容受上下文窗口限制，太多就得截斷，要在細節與篇幅之間取捨。

STEP 1切塊：把長文件切成可檢索的小單位

每一塊都可以單獨被索引、嵌入與檢索。但「切多大」有拉扯：

小塊（約 100–256 token）

有利於精準比對。

大塊（約 1024 token 以上）

能給 LLM 比較完整的上下文。

常見做法，非最佳值 多數情況用 300–500 token 的塊，相鄰塊重疊 10–20%。

常見切法：固定長度 · 遞迴（依段落／句子逐層切）· 語意切塊 · 保留文件結構。

STEP 2嵌入與向量搜尋：用「意思」找資料

  • 嵌入：把文字轉成一串數字（向量）；意思相近，距離就近。
  • 相似度：文字檢索最常用 cosine 相似度。
  • 向量資料庫：專門存向量並快速找最近的；資料量大時用近似最近鄰（ANN）加速。
  • 取前 k 筆：經驗上 k 為 3–5 適合聚焦的問題，10–20 適合較廣的問題。

STEP 3只靠語意不夠：混合搜尋與重排序

問題：嵌入擅長抓語意，卻可能漏掉必須精確吻合的字串。
搜尋「Error code TS-999」時，可能找到一般的錯誤代碼說明，卻漏掉剛好寫 TS-999 的那份。

BM25以關鍵字比對為主的排序函式，建立在 TF-IDF 的概念上。
混合搜尋BM25 與嵌入各找一批，用排名融合合併、去重。
重排序（Anthropic 實驗）先撈出前 150 塊，由重排序模型打分，再選前 20 塊給 LLM。

名詞：dense（稠密）＝依語意；sparse（稀疏）＝依關鍵字；reranking＝重新排序讓最相關的排前面。實驗結論：「嵌入＋BM25」優於只用嵌入。

UPGRADE切塊會丟掉上下文，怎麼辦？

傳統 RAG

某一塊只寫著：
「公司營收比上一季成長 3%」

哪家公司？哪一季？不知道，所以很難被對的問題找到。

Contextual Retrieval

用 LLM 替每一塊補上一小段背景說明：
「這一塊來自某公司某季財報……公司營收比上一季成長 3%」

（示意）背景說明通常 50–100 token，加在塊前面，再做嵌入並建立 BM25 索引。

EVIDENCE效果有多大？檢索失敗率逐步下降

指標是「1 − recall@20」：前 20 塊裡沒撈到相關內容的比例，越低越好。資料來自 Anthropic 的實驗報告。

讀圖提醒：35%、49%、67% 是「失敗率的相對降低幅度」，不是「準確率提升幅度」。替每塊產生背景說明的一次性成本，Anthropic 估計約為每百萬個文件 token $1.02（搭配 prompt caching）。

COMPARERAG、微調、提示工程有什麼不同？

做什麼優點限制
微調用領域資料繼續訓練模型專門任務表現好成本高、要大量資料，知識變動要重做
提示工程設計更好的指令改風格與結構無法替模型增加新知識
RAG執行時取外部脈絡再附進提示詞知識易更新、降低幻覺取決於檢索品質與資料新鮮度

三者不是互斥：微調建立專業、提示工程調整互動、RAG 提供彈性與時效，可以搭配。

EVOLUTIONRAG 的演進：從「查一次」到「會判斷」

Naive檢索 → 閱讀，找到就用。
Advanced稠密檢索、重排序、多跳檢索。
Modular元件可替換，整合外部工具與 API。
Graph用圖結構做關聯推理。
Agentic代理決定要不要檢索、怎麼改寫查詢、證據夠不夠。

Corrective RAG

先評估檢索到的文件是否相關；不夠就改寫查詢或改用網路搜尋補充。

Adaptive RAG

先判斷問題複雜度：不檢索、檢索一次，或多步檢索。

為什麼要走向代理式？傳統流程固定、單向，不擅長邊查邊修正。代理常用四種模式：反思、規劃、工具使用、多代理協作。

CHOOSE更複雜不等於更好

Agentic 不是萬用預設

會增加協調複雜度、延遲與運算成本；簡單查詢用模組化 RAG 通常就夠。

檢索品質仍是瓶頸

代理式推理無法彌補一直很差的檢索，先把索引與檢索做好。

自主性需要邊界

設定規劃步數上限、工具權限與停止條件。

小知識庫也許不需要 RAG

Anthropic 指出：知識庫小於 200,000 token（約 500 頁）時，可以直接全部放進提示詞。

RISKSRAG 帶來的新風險

資料投毒

惡意或誤導內容被放進知識庫，被檢索到就會誤導答案。

提示注入

惡意指令藏在檢索回來的文字裡，可能蓋過原本的指令。

敏感資料外洩

私人資料可能被檢索或生成出來，需要存取控制與內容過濾。

外部 API 依賴

第三方服務出問題時，整個系統跟著受影響。

原則：檢索回來的任何內容，在證明安全之前都視為不可信。維運上也要定期更新知識庫，避免回答過時內容。

RECAP五句話帶走

  1. RAG ＝ 先查資料，再讓 LLM 根據資料回答。
  2. 流程分兩階段：離線建索引、線上檢索＋生成。
  3. 只靠語意會漏掉精確字串，所以常用混合搜尋＋重排序。
  4. 切塊會丟上下文，Contextual Retrieval 為每塊補上背景。
  5. 檢索內容要當作不可信輸入來防護。

QUIZ小測驗：點選答案看解析

Q1. 搜尋「Error code TS-999」時，只用嵌入搜尋可能出什麼問題？

嵌入抓的是語意，不保證精確字串一定被撈到。補上 BM25 這類關鍵字比對就能改善。（wiki：C40）

Q2. 同時使用 Contextual Embeddings 與 Contextual BM25，檢索失敗率降低多少？

35% 是只用 Contextual Embeddings；49% 是再加 Contextual BM25；67% 是再加重排序。（wiki：C52–C54）

Q3. 對於檢索回來的內容，比較安全的預設態度是？

資料投毒與提示注入都可能藏在被檢索到的內容裡。（wiki：C94）
